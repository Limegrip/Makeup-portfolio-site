# Онлайн-запись: функция в Yandex Cloud

Сайт (GitHub Pages) показывает календарь и форму, а эта функция:
- читает Яндекс Календарь и отдаёт свободное время (только «свободно/занято», без имён);
- по заявке создаёт в календаре событие «Заявка: услуга — имя» со статусом «под вопросом»
  и шлёт сообщение в Telegram.

Telegram из Yandex Cloud недоступен (в РФ он работает только через VPN), поэтому
сообщение идёт через посредника в Google Apps Script — `telegram-relay.gs`:
функция → Google → Telegram. Если посредник не ответит, заявка всё равно остаётся
в календаре; в ответе функции поле `telegram` покажет причину.

Услуги, длительности, часы записи (10:00–22:00), минимальный срок до записи и запас на дорогу — в начале `booking.py`.
Проверка логики без Яндекса: `python3 backend/test_booking.py`.

## Настройка (один раз)

1. **Пароль приложения Яндекса.** id.yandex.ru → Безопасность → Пароли приложений →
   «Календарь (CalDAV)» → создать. Сохраните пароль — он показывается один раз.
2. **Бот в Telegram.** @BotFather → `/newbot` → получите токен. Напишите своему боту
   любое сообщение, откройте `https://api.telegram.org/bot<ТОКЕН>/getUpdates` и найдите
   `"chat":{"id": ...}` — это ваш chat id (или спросите у @userinfobot).
3. **Посредник для Telegram.** script.google.com → «Новый проект» → вставить код из
   `telegram-relay.gs` → сохранить. Настройки проекта → «Свойства скрипта»:
   `TG_BOT_TOKEN`, `TG_CHAT_ID` и `RELAY_SECRET` — любая длинная случайная строка.
   «Начать развертывание» → «Новое развертывание» → «Веб-приложение», запуск от вашего
   имени, доступ «Все» → разрешить доступ → скопировать URL веб-приложения.
4. **Функция.** console.yandex.cloud → Cloud Functions → «Создать функцию» `booking`:
   - среда выполнения **Python 3.12**, способ — ZIP-архив (`booking.py` + `requirements.txt`);
   - точка входа `booking.handler`, таймаут 20 с, память 256 МБ;
   - переменные окружения:

     | Переменная | Значение |
     |---|---|
     | `YANDEX_LOGIN` | логин Яндекса, например `name@yandex.ru` |
     | `YANDEX_APP_PASSWORD` | пароль из шага 1 |
     | `CALENDAR_NAME` | название календаря; пусто — первый календарь |
     | `RELAY_URL` | URL веб-приложения из шага 3 |
     | `RELAY_SECRET` | тот же `RELAY_SECRET`, что в свойствах скрипта |
     | `ALLOWED_ORIGIN` | `https://limegrip.github.io null` — сайты через пробел; `null` — страница, открытая с диска |
     | `BUFFER_MIN` | запас на дорогу в минутах, по умолчанию `60` |

   - в «Обзоре» включите **«Публичная функция»** и скопируйте ссылку для вызова.
5. Вставьте ссылку в `index.html`: `<section class="booking" id="booking" data-api="ССЫЛКА">`.

## Переключение на календарь Насти

Поменять `YANDEX_LOGIN`, `YANDEX_APP_PASSWORD` (пароль приложения из её аккаунта),
при необходимости `CALENDAR_NAME`. Чтобы заявки приходили Насте, поменять `TG_CHAT_ID`
в свойствах скрипта-посредника (и написать боту с её аккаунта). Код и сайт трогать не нужно.

## Как Настя пользуется

- Выходной или отпуск — событие «на весь день» в календаре: день пропадает с сайта.
- С сайта можно записаться только так, чтобы услуга уложилась в 10:00–22:00.
  Ранние и поздние записи Настя ставит в календарь сама — сайт их учтёт как занятое время.
- Событие с пометкой «свободна» (не занята) запись не блокирует.
- Заявка приходит в Telegram и появляется в календаре; после созвона Настя правит или
  удаляет событие, и сайт сразу это учитывает.
